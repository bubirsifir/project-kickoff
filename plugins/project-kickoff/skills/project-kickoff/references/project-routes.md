# Project-Type Routes

Select one or more routes. Hybrid projects inherit only relevant questions from each route.

## Idea or product exploration

Prioritize problem evidence, target user, current alternatives, differentiated value, riskiest assumption, validation method, and smallest useful outcome. Do not prematurely lock technology or a long feature list.

## Landing page or marketing website

Prioritize audience, offer, conversion goal, primary CTA, information hierarchy, required proof, content ownership, brand assets, SEO/search intent, forms, analytics, legal pages, localization, and publishing destination.

Usually skip accounts, complex roles, and databases unless the site genuinely needs them.

## Corporate or content website

Prioritize audiences, content types, navigation, editorial ownership, CMS needs, search, localization, accessibility, SEO, migration, redirects, analytics, and publishing workflow.

## Web application or SaaS

Prioritize personas, tenancy, roles, main workflow, onboarding, permissions, MVP limits, billing, subscription states, data model, notifications, integrations, admin/support tools, auditability, analytics, security, and lifecycle events such as export, cancellation, and deletion.

## Mobile application

Prioritize mobile use context, iOS/Android sequence, required device capabilities, offline behavior, background work, notifications, authentication, deep links, store distribution, review constraints, accessibility, analytics, and release/update ownership.

## Ecommerce

Prioritize catalog structure, inventory, pricing, tax and currency, shipping regions, checkout, payment provider, returns, promotions, customer accounts, order lifecycle, transactional messages, fraud/risk, admin operations, analytics, and legal obligations. Do not invent jurisdiction-specific rules.

## AI product or agent

Prioritize exact AI job, input and output, knowledge sources, freshness, tools/actions, autonomy boundary, human approval, failure impact, fallback, memory, privacy, evaluation set, quality threshold, latency, cost limits, abuse controls, traceability, and user disclosure.

Treat “add AI” as an unresolved product decision, not a complete requirement.

## Automation or internal tool

Prioritize trigger, actor, source systems, destination systems, credentials/ownership, approval steps, exception handling, retries, idempotency, audit log, notifications, manual override, operating schedule, and recovery.

## API or backend service

Prioritize consumers, contract, authentication, authorization, data ownership, versioning, rate limits, idempotency, error model, observability, privacy, availability, compatibility, and documentation.

## Existing project change

Inspect the current structure before interviewing. Prioritize current behavior, desired behavior, reason for change, affected users, protected behavior, migrations, compatibility, rollout, rollback, acceptance tests, and existing conventions. Avoid reopening settled product decisions unrelated to the change.

## Bug fix

When the defect and expected behavior are already clear, do not run full discovery. Confirm reproduction, expected result, scope, regression risk, and verification only. Then proceed if implementation is authorized.
